# 新しい開発者向けガイド

このサイトの開発を初めて担当する方向けの案内です。作業前に一通り目を通してください。

## このサイトの目的

LA Kansai Club（ロサンゼルス在住の関西出身者・関西ファン向けコミュニティ）の公式サイトです。企業サイトではなくコミュニティサイトであり、初めて訪れた人が10秒以内に「何の団体か」「楽しそう」「参加したい」と感じられることを最優先の目的としています。

もう一つ、このプロジェクトで最も重要な要件は「役員がコードを書かずに更新できること」です。技術的に高度な実装より、非技術者でも長期間・安全・簡単に運営できることを優先してください。

## 設計思想

- シンプル・親しみやすい・信頼感・ロサンゼルスらしい開放感・日本らしい上品さの5つを軸にしたデザイン
- 白を基調に、写真を主役にし、情報量と文字数を減らす方向で判断する
- 派手なアニメーションは使わない、読み込み速度を重視する
- 詳しくは `DESIGN_RULES.md` を参照

## デザインルール

配色・タイポグラフィ・余白・ボタン/カード/アイコンのルール・写真選びのルール・文章の書き方・ページ追加時のルールは、すべて `DESIGN_RULES.md` にまとまっています。UIに関わる作業をする前に必ず読んでください。トップページの確定デザインモック（Version 1）は次のURLで確認できます。

https://claude.ai/code/artifact/98cf4d0e-ff57-43c3-b39e-e29a09c99050

## 更新方法（コンテンツ運用）

日常のイベント・News・Galleryの更新は、Sanity（ヘッドレスCMS）の管理画面からブラウザだけで行う設計です。理事はコードに触れず、GitHubやVercelのアカウントも意識せずに更新できます。運用の全体設計は `OPERATIONS.md` にまとまっています。

## Sanity運用

- 各理事は自分のメールアドレスでSanityに招待され、Editor（編集者）権限で記事を編集・公開します
- メンバーの追加・削除ができるAdministrator権限は、会長・副会長など1〜2名に限定します
- Sanity自体の契約・組織管理は、個人ではなくクラブ専用の管理用Googleアカウントに紐づけます
- 詳細は `OPERATIONS.md` の「1〜7」を参照してください

## デプロイ方法

- コードはGitHub（クラブの管理アカウント名義のOrganization）で管理します
- Vercel（同じく管理アカウント名義のTeam）と連携し、GitHubのmainブランチにpushすると自動的にビルド・公開されます
- 環境変数（Sanityの接続情報など）はコードに直接書かず、Vercelのプロジェクト設定画面で管理します
- 詳しい技術情報（使用技術・Node.jsバージョン・環境変数一覧・フォルダ構成・バックアップ方法）は `OPERATIONS.md` の「8. 開発者向け情報」を参照してください

## 開発を引き受けるときの心構え

このプロジェクトには明確な開発ルールがあります。`CLAUDE.md` にも記載していますが、特に次の点は必ず守ってください。

- 実装は必ず「提案 → 理由説明 → 承認 → 実装」の順で進め、デザイン・ページ構成・新機能・使用ライブラリ・文章の大幅な変更を独自判断で行わない
- デザインモックと`DESIGN_RULES.md`が最優先の仕様であり、実装中に「より良いデザイン」と判断して変更しない
- サイト全体を一度に実装せず、1ページずつ完成・確認・承認してから次に進む

## 引き継ぎ時のチェックリスト

新しい開発者が加わる、または既存の開発者が離れるときに確認する項目です。

- [ ] クラブの管理用Googleアカウント経由で、GitHub Organization・Vercel Team・Sanity Organizationにアクセスできることを確認した
- [ ] `git clone` してローカルで `npm install` → `npm run dev` が問題なく起動することを確認した
- [ ] Vercelの環境変数一覧を確認し、`.env.local`等をローカルにも用意した（本ファイルおよび`OPERATIONS.md`参照）
- [ ] `DESIGN_RULES.md` と `OPERATIONS.md` を読み、デザイン・運用のルールを理解した
- [ ] 直近のSanityデータのバックアップがいつ取られたか確認した。古い場合は新たに書き出しを依頼した
- [ ] 前任の開発者がいる場合、未対応のタスクや既知の不具合の引き継ぎを受けた
- [ ] 作業を始める前に、クラブの理事（Administrator権限を持つ担当者）と今後の作業方針について合意した
